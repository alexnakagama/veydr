# Security baseline (F1)

Implements design D2. A compromised renderer is equivalent to code execution as the user (the UI can edit and start commands), so the defenses aim at preventing renderer compromise.

* **Window**: `contextIsolation`, `sandbox`, no `nodeIntegration` (also in workers/subframes), no `webviewTag`, `webSecurity`, no drag-drop navigation, no spellcheck (`src/main/app/webPreferences.ts`, unit-tested). DevTools are available only in unpackaged builds.
* **Process sandbox**: `app.enableSandbox()`. E2E launches Electron with `chromiumSandbox: true` (Playwright otherwise adds `--no-sandbox`) and asserts that neither the main process nor any process reported by `app.getAppMetrics()` has `--no-sandbox` on its command line. The flag only ever appears on the main process, so this detects a disabled sandbox; it does not prove sandbox strength. Verified on one Debian 13 host (see `deferred-checks.md` for other distributions).
* **Content**: served from `app://veydr/` with a CSP header on every response, including errors; path traversal and unknown file types are refused.
* **IPC**: every operation is declared once in `src/shared/api/contract.ts` (channel, request schema, response schema) and `window.veydr` is derived from it. One registration helper checks the sender is the main frame of the application window showing bundled content, rejects extra arguments, validates the request with zod, validates the handler's response against the declared schema (so a value outside it, such as an unmasked secret, is never sent; only the failing field paths are logged), and maps errors to typed results. Rejections are recorded in the in-memory diagnostic log (stderr). The preload exposes named operations only, forwards at most one argument, and never passes the IPC event object to the page. Event subscriptions go through the same gate; main tracks subscribers per `webContents` and document, drops a reloaded document's subscriptions, never sends to a destroyed `webContents`, and validates event payloads before sending. Rejection is verified against real Electron frames (a second window with the same preload is refused).
* **Failure handling**: a failed UI load, a missing renderer bundle, a dead renderer, or an uncaught exception shows an error dialog while running commands are stopped as on a termination signal (at most 10 seconds, see `docs/processes.md`), then exits (E2E-tested with the dialog stubbed); unhandled rejections are logged.
* **Not yet in place or verified**: packaged-build fuses and other packaged-only behavior; see `deferred-checks.md` (task 9.1).
* **Descriptors of started programs** (found in the L4 review, fixed in L5): Node's `child_process.spawn` relies on close-on-exec, and Electron's main process holds many descriptors without it (Chromium IPC sockets and pipes, files in the configuration directory such as Local Storage and GPU caches). Every program Veydr starts — commands, the login shell that reads the environment, the editor — is therefore started through a small exec wrapper (`src/main/platform/linux/executable.ts`): `bash`, with an empty environment, closes every descriptor above 2 and execs `env -i`, which sets exactly the program's environment and execs it (through `nice -n 0` if its path contains `=`). The program keeps the PID the wrapper started with. Verified by an integration test with inherited descriptors 3–12 and by E2E (a started command holds only descriptors 0–2). The wrapper fails closed (L5 review, L5-02): if `bash` or `env` is missing, nothing is started and the start fails with the reason (also logged as `process.exec-wrapper-unavailable`); without `/proc` the wrapper exits with status 125 instead of running the program. `nice` is needed only for a path containing `=`, which is refused without it. All supported distributions ship these tools.
* **Process output** (L6, `docs/logs.md`): the renderer shows output as React text nodes only; a unit test fails if renderer code uses an HTML-injection API (`dangerouslySetInnerHTML`, `innerHTML`, `insertAdjacentHTML`, …). The in-house parser (`src/shared/ansi`) turns SGR sequences into styles (applied through the DOM style API, which the CSP's `style-src 'self'` allows) and removes every other escape sequence and control character (OSC 52 clipboard writes, OSC 8 links, titles, cursor movement, DCS/APC/PM/SOS, C1 forms); a seeded property test checks that no control character survives, and E2E checks that markup is not executed, the title and clipboard are unchanged, and no link or image element appears. Exact secret values of the command are redacted in main before a line is kept, so they never reach the renderer through logs (best effort, see `docs/logs.md`). Copying uses the browser copy command of a user action, so no clipboard permission is granted (every permission request is still denied). Log batches and reads are validated against the contract like every IPC message (cheap per-line checks, at most 1,000 lines per batch and 5,000 per read). Output is never written to disk.
* **Environment preview**: secret overrides are masked until revealed; values of the login environment itself (which may include tokens exported in shell configuration files) are sent to the renderer unmasked when the user opens a command's environment view (accepted: the spec requires masking of secret overrides only).
* **Lint boundaries** (best-effort guardrail, not a security boundary): platform implementation imports and `process.platform` reads are confined to `src/main/platform/index.ts` and the composition root (`src/main/index.ts`, which is exempt from these rules and only calls `selectPlatform`). Across `src/**`: restricted imports/properties, namespace imports of `os`/`process`, aliasing `process`, `globalThis.process.platform`, and `import()`/`require` of platform paths. Additionally in `src/main/**`: *any* `.platform` property read or destructuring (this catches renamed default imports, `require('os').platform()` and `import('node:os')` results, at the price of flagging unrelated `.platform` properties, so name such fields differently), `process.getBuiltinModule`, and dynamic imports with a non-literal specifier.
* **Known lint limitations** (fixtures cover everything above, none of the below): `Reflect.get(process, 'platform')`, computed keys built at runtime, OS inference through `os.type()`/`os.release()`/`os.version()`, `eval`/`new Function`, and any code outside `src/` (scripts, tests). The rules cover only what a reviewer would otherwise have to spot by eye; code review remains necessary.
