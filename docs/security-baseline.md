# Security baseline (F1)

Implements design D2. A compromised renderer is equivalent to code execution as the user (the UI can edit and start commands), so the defenses aim at preventing renderer compromise.

* **Window**: `contextIsolation`, `sandbox`, no `nodeIntegration` (also in workers/subframes), no `webviewTag`, `webSecurity`, no drag-drop navigation, no spellcheck (`src/main/app/webPreferences.ts`, unit-tested). DevTools are available only in unpackaged builds.
* **Process sandbox**: `app.enableSandbox()`. E2E launches Electron with `chromiumSandbox: true` (Playwright otherwise adds `--no-sandbox`) and asserts that neither the main process nor any process reported by `app.getAppMetrics()` has `--no-sandbox` on its command line. The flag only ever appears on the main process, so this detects a disabled sandbox; it does not prove sandbox strength. Verified on one Debian 13 host (see `deferred-checks.md` for other distributions).
* **Content**: served from `app://veydr/` with a CSP header on every response, including errors; path traversal and unknown file types are refused.
* **IPC**: one registration helper checks the sender is the main frame of the application window showing bundled content, rejects extra arguments, validates with zod, and maps errors to typed results. Rejections are recorded in the in-memory diagnostic log (stderr). The preload exposes named operations only. Rejection is verified against real Electron frames (a second window with the same preload is refused).
* **Failure handling**: a failed UI load, a missing renderer bundle, or a dead renderer shows an error dialog and exits (E2E-tested with the dialog stubbed); unhandled rejections are logged. Quit orchestration for managed processes replaces the bare exit in group L4.
* **Not yet in place or verified**: packaged-build fuses and other packaged-only behavior; see `deferred-checks.md` (task 9.1).
* **Lint boundaries** (best-effort guardrail, not a security boundary): platform implementation imports and `process.platform` reads are confined to `src/main/platform/index.ts` and the composition root (`src/main/index.ts`, which is exempt from these rules and only calls `selectPlatform`). Across `src/**`: restricted imports/properties, namespace imports of `os`/`process`, aliasing `process`, `globalThis.process.platform`, and `import()`/`require` of platform paths. Additionally in `src/main/**`: *any* `.platform` property read or destructuring (this catches renamed default imports, `require('os').platform()` and `import('node:os')` results, at the price of flagging unrelated `.platform` properties, so name such fields differently), `process.getBuiltinModule`, and dynamic imports with a non-literal specifier.
* **Known lint limitations** (fixtures cover everything above, none of the below): `Reflect.get(process, 'platform')`, computed keys built at runtime, OS inference through `os.type()`/`os.release()`/`os.version()`, `eval`/`new Function`, and any code outside `src/` (scripts, tests). The rules cover only what a reviewer would otherwise have to spot by eye; code review remains necessary.
